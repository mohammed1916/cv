2. VISUALIZER COMPONENT STRUCTURE
================================================================================

A complete visualizer has these key sections:

A. IMPORTS (12-15 standard imports)
   - React hooks (useState, useMemo, useCallback)
   - Framer Motion (for animations)
   - Component dependencies (DockableWorkspace, FloatingPanel, etc.)
   - Custom hooks (usePlaybackState, useCodeVisualConnectivity, etc.)
   - Config access (getExamples from examplesRegistry)
   - CSS import

B. STEP GENERATOR FUNCTION
   - Simulates algorithm step-by-step
   - Takes problem inputs as parameters
   - Returns array of step objects
   - Each step contains: activeLine, state variables, message
   - Typical length: 100-150 lines

C. VISUALIZATION COMPONENT(S)
   - BinaryVisualization (or ProblemSpecific)
   - Shows current step state visually
   - Uses motion.div for animations
   - Color-codes variables/states
   - VisualizationPanel wrapper with examples

D. MAIN EXPORT COMPONENT
   - Manages state with useState
   - Gets examples from registry with getExamples()
   - Generates steps with useMemo
   - Uses playback hooks (usePlaybackState, useCodeVisualConnectivity)
   - Configures dock panels with code + visualization
   - Renders DockableWorkspace + FloatingPanel + PatternOverlay

================================================================================
3. STEP OBJECT STRUCTURE
================================================================================

Each step must contain:
{
  activeLine: number,                    // Code line to highlight (1-indexed)
  [variable1]: any,                      // All current state variables
  [variable2]: any,
  [result]: array|value,                 // Result/output at this step
  message: string,                       // User-friendly description
  relatedLines?: number[],               // Optional: related code lines
  done?: boolean                         // Optional: marks completion
}

Example from AddBinaryVisualizer:
{
  activeLine: 7,
  i: 1,
  j: 2,
  carry: 0,
  result: [1],
  a_idx: 1,
  b_idx: 2,
  a_bit: 1,
  b_bit: 0,
  sum: 1,
  message: "Calculate: 1 + 0 + 0 = 1"
}

================================================================================
6. COMPLETE COMPONENT LIFECYCLE
================================================================================

1. User selects an example
   -> applyEx() updates state and resets playback

2. Example change triggers useMemo
   -> generateSteps() creates step array
   -> Each step maps to code line via relatedLines

3. User presses Play/Step
   -> usePlaybackState advances stepIndex
   -> Current step retrieved: step = steps[stepIndex]

4. Step change propagates:
   -> Code panel highlights activeLine
   -> Visualization component re-renders with new step data
   -> Animations trigger via motion.div

5. Pattern Overlay (optional)
   -> Shows code execution pattern visualization
   -> Toggleable via PlaybackControls

================================================================================
7. LAYOUT STRUCTURE
================================================================================

Three-Part Composition:

A. DOCKABLE WORKSPACE (Main content)
   - Left/Right split layout
   - Panels:
     * id: 'code'    - CodeTracePanel
     * id: 'viz'     - Custom visualization
   - Initial layout: { rows: [['code', 'viz']], minimized: [] }
   - Panels are resizable and draggable

B. FLOATING PANEL (Always visible)
   - Title: "Playback Controls"
   - Contains PlaybackControls component
   - Controls: Play/Pause, Step Back/Forward, Reset, Speed
   - Toggle for Pattern Overlay

C. PATTERN OVERLAY (Conditional)
   - Renders if: showPatternOverlay && step
   - Shows code execution flow visualization
   - Optional but recommended

================================================================================
8. KEY HOOKS & THEIR PURPOSES
================================================================================

usePlaybackState(stepsLength)
  Returns: stepIndex, setStepIndex, stepForward, stepBack, togglePlay,
           handleReset, isPlaying, speed, setSpeed, isDone
  Purpose: Manages playback state and speed

useCodeVisualConnectivity({ steps, stepIndex, onStepJump })
  Returns: { highlightedLines, handleLineSelect }
  Purpose: Links code lines to step jumps

usePatternOverlay()
  Returns: { showPatternOverlay, setShowPatternOverlay, activeLineDom, setActiveLineDom }
  Purpose: Controls pattern overlay visibility

useSolutionCode(slug)
  Returns: Code lines array for solution
  Purpose: Fetches problem solution code

getExamples(slug)
  Returns: Examples array from registry
  Purpose: Gets problem-specific examples

================================================================================
9. ANIMATION & INTERACTION
================================================================================

Motion Library (Framer Motion):
  <motion.div
    initial={{ opacity: 0, y: -10 }}
    animate={{ opacity: 1, y: 0 }}
    style={{ scale: isCurrent ? 1.1 : 1 }}
  >
    Content
  </motion.div>

Event Handlers:
  - onClick handlers on example buttons
  - onLineSelect for code interactivity
  - onPlayToggle, onNext, onPrev for controls
  - onSpeedChange for speed slider

State Updates:
  - immutable: use spread operator [...array], {...obj}
  - avoid mutations that break animations
  - useMemo for expensive computations
